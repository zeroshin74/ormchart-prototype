치료 결과 화면을 벗어난 상태입니다. 재진입하면 사용자별로 저장된 마지막 펼침 상태가 복원됩니다.
저장하지 않은 소견 입력값은 실제 화면과 동일하게 유지되지 않습니다.

2. 화면 개요

환자의 당일 오더를 8개 오더분류 섹션으로 나누어 표시하고, 수행/결과 입력을 한 화면에서 처리한다. 핵심 UX 결정은 두 가지다.

  • 행 상세는 기본 접힘(기초검사 제외) — 목록 스캔 효율 우선
  • 펼침/접힘은 사용자별 설정으로 저장·복원 — 재진입 시 반복 조작(VOC)을 제거. 환자 단위가 아닌 사용자 단위 저장

4.3 행 상세 (치료)

시작/종료 시간 입력 + 빠른 입력 칩 + 치료 소견 텍스트영역(4000 bytes 제한, 우하단 카운터)을 하나의 폼 컨테이너로 구성. 칩 클릭 시 소견에 문구가 추가/제거되고 카운터가 갱신된다. 기타 섹션의 상세는 판독문/처치기록(읽기 블록) 또는 측정값 테이블(기초검사).

7. 상태 유지 정책

  • 저장 단위 — 사용자 × 섹션 × 행. 환자 단위 아님 (환자를 바꿔도 사용자의 화면 설정은 동일하게 적용)
  • 저장 시점 — 조작 즉시 자동 저장. 별도 저장 버튼·설정 화면 없음
  • 복원 시점 — 화면 재진입·새로고침 시. 프로토타입은 localStorage, 실서비스는 사용자 설정 API로 대체
  • 제외 대상 — 저장하지 않은 소견 입력값은 유지되지 않음 (기존 저장 동작과 동일)

저장 데이터 구조 (프로토타입 기준, 키 ormchart-proto-user-state):

{
  "cards": { "treat": false, "inject": false, ... },   // 섹션 카드 닫힘 여부
  "rows":  { "treat": [true, false, false], ... }      // 섹션별 행 상세 펼침 여부 (행 순서 기준)
}

9. 개발 참고

  • 행 상세는 colspan 상세 행으로 구현. 상세 열림 여부와 무관하게 테이블 목록(오더 행)은 항상 유지
  • 필 토글의 채움 상태는 별도 상태값이 아니라 행 펼침 상태로부터 파생 (모두 펼침 → "펼침" 채움, 모두 접힘 → "접힘" 채움, 그 외 혼합)
  • 복원 순서: 화면 렌더(기본값) → 저장값 로드 → 카드/행 상태 덮어쓰기 → 토글 표시 갱신
