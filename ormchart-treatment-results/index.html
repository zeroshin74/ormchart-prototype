치료 결과 화면을 벗어난 상태입니다. 재진입하면 각 섹션의 항상 펼침 설정대로 표시되며, 이 설정은 다른 환자 화면에서도 동일하게 적용됩니다.
행 개별 펼침 조작과 저장하지 않은 소견 입력값은 유지되지 않습니다.

2. 화면 개요

환자의 당일 오더를 8개 오더분류 섹션으로 나누어 표시하고, 수행/결과 입력을 한 화면에서 처리한다. 핵심 UX 결정은 두 가지다.

  • 행 상세는 기본 접힘(기초검사 제외) — 목록 스캔 효율 우선
  • "항상 펼침"은 사용자별 설정(규칙)으로 저장 — 환자를 바꾸거나 화면을 나갔다 와도 동일하게 적용되어 재진입 시 반복 조작(VOC)을 제거. 행 개별 조작은 세션 한정 임시 동작이며 설정에 영향을 주지 않음

4. 컴포넌트 정의

4.1 항상 펼침 — ON/OFF 스위치

현재 화면 상태가 아닌 미래에 적용될 규칙을 서술하는 설정 컨트롤. "항상"이라는 레이블이 규칙임을 약속하므로, 사용자가 행을 개별로 펼쳐 화면이 스위치 값과 잠시 달라져도 모순으로 읽히지 않는다.

상태표시동작
ON트랙 채움(accent) + 노브 우측화면 진입 시 해당 섹션의 모든 행 상세를 펼쳐서 렌더링. 전환 즉시 현재 화면에도 적용
OFF트랙 회색 + 노브 좌측화면 진입 시 모든 행 상세를 접어서 렌더링. 전환 즉시 현재 화면에도 적용

행 조작과의 분리(핵심 규칙) — 행 상태 텍스트(▶/▼) 클릭은 스위치 값을 변경하지 않는다. 행 개별 조작은 세션 한정 임시 동작이며 저장되지 않는다.

4.3 행 상세 (치료)

시작/종료 시간 입력 + 빠른 입력 칩 + 치료 소견 텍스트영역(4000 bytes 제한, 우하단 카운터)을 하나의 폼 컨테이너로 구성. 칩 클릭 시 소견에 문구가 추가/제거되고 카운터가 갱신된다. 기타 섹션의 상세는 판독문/처치기록(읽기 블록) 또는 측정값 테이블(기초검사).

7. 상태 유지 정책

  • 저장 대상 — 각 섹션의 "항상 펼침" 스위치 값 하나뿐. 행 개별 펼침, 섹션 카드 열림/닫힘은 저장하지 않음
  • 저장 단위 — 사용자 × 섹션. 환자 단위 아님 — 어떤 환자 화면에서도 동일한 설정이 적용됨
  • 저장 시점 — 스위치 조작 즉시 자동 저장. 별도 저장 버튼·설정 화면 없음
  • 복원 시점 — 화면 재진입·환자 변경·새로고침 시 스위치 값대로 렌더링. 프로토타입은 localStorage, 실서비스는 사용자 설정 API로 대체
  • 제외 대상 — 행 개별 조작(세션 임시), 저장하지 않은 소견 입력값

저장 데이터 구조 (프로토타입 기준, 키 ormchart-proto-user-prefs):

{
  "prefs": {
    "treat": false,   // 치료 · 항상 펼침 OFF
    "diag":  false,   // 진단의학(장문형) · 항상 펼침 OFF
    "basic": true,    // 기초검사 · 항상 펼침 ON
    ...               // 주사(inject)는 스위치가 없어 키 자체가 없음
  }
}

9. 개발 참고

  • 행 상세는 colspan 상세 행으로 구현. 상세 열림 여부와 무관하게 테이블 목록(오더 행)은 항상 유지
  • 스위치 값과 행 상태는 단방향 — 스위치 전환은 행 상태를 일괄 변경하지만, 행 개별 조작은 스위치 값을 변경하지 않음 (파생 관계 아님)
  • 렌더 순서: 화면 렌더 → 저장된 스위치 값 로드 → 각 섹션 행 상태를 스위치 값대로 설정. 행·카드의 이전 임시 상태는 복원하지 않음
  • 접근성 — 스위치는 role="switch" + aria-checked로 구현
