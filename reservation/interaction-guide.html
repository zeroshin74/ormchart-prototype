01

기본 개념

캘린더는 의사, 검사, 치료 일정 단위의 카드이며 사용자가 페이지 단위로 자유롭게 배치할 수 있습니다.

사용자 동작
좌측 목록에서 캘린더 노출 여부를 선택하고, 중앙 영역에서 페이지별 캘린더를 확인합니다.
개발 기준
캘린더는 Provider Id로 식별하고, 페이지는 Provider Id 배열 묶음으로 관리합니다.

02

보기 모드

정렬 메뉴에서 기본 보기, 하나 보기, 모두 보기, 페이지 구성 편집으로 진입합니다.

사용자 동작
정렬 버튼을 열어 원하는 보기 방식을 선택합니다. 설정 버튼은 아이콘만 남겨 공간을 확보합니다.
개발 기준
편집 저장 후에는 항상 캘린더 기본 보기로 돌아오며, 사용자가 구성한 페이지와 폭을 기준으로 표시합니다.

03

페이지 구성 편집

편집 모드에서는 페이지 번호가 버튼화되고, 페이지 추가와 순서 변경이 가능합니다.

사용자 동작
페이지 번호를 클릭해 이동하고, 번호를 드래그해서 페이지 순서를 바꿉니다. + 버튼으로 빈 페이지를 추가합니다.
개발 기준
편집 중에는 다른 보기 모드로 변경하지 않고, 우측 상단은 취소/저장 액션만 노출합니다.

04

빈 페이지

캘린더가 없는 페이지는 비어 있음을 명확히 알리고, 추가와 삭제 액션을 제공합니다.

사용자 동작
빈 페이지 중앙의 캘린더 추가 또는 페이지 삭제 버튼을 선택합니다.
개발 기준
페이지 배열은 유지하되, 화면에는 Empty State 컴포넌트를 표시합니다. 캘린더가 있으면 삭제할 수 없습니다.

05

캘린더 Check / UnCheck

좌측 체크박스는 노출 필터이며, 페이지 이동을 강제로 발생시키지 않습니다.

사용자 동작
보고 싶은 캘린더만 체크합니다. 체크한 캘린더가 다른 페이지에 있으면 현재 페이지를 유지하고 토스트로 안내합니다.
개발 기준
숨긴 캘린더의 폭 저장값을 우선 복원하되, 최소 폭과 화면 폭 제약 안에서 가능한 폭으로 보정합니다.

06

캘린더 폭 조정

캘린더 사이 경계선을 드래그하면 인접한 두 캘린더만 폭을 주고받습니다.

사용자 동작
캘린더 사이 세로 경계선을 드래그합니다. 엑셀 열 너비 조정처럼 인접 열만 변경됩니다.
개발 기준
왼쪽 캘린더가 넓어지면 오른쪽 인접 캘린더가 같은 만큼 줄고, 다른 캘린더는 변하지 않습니다.

07

캘린더 Drag & Drop

캘린더 헤더를 드래그하여 같은 페이지의 순서를 바꾸거나, 편집 모드에서 다른 페이지로 이동합니다.

사용자 동작
의사명/더보기 헤더를 드래그합니다. 삽입 위치에는 3px 파란 세로선이 표시됩니다.
개발 기준
드롭 위치는 대상 캘린더의 좌/우 가까운 경계로 before/after를 계산합니다. 마지막 캘린더 오른쪽은 페이지 끝 삽입입니다.

08

캘린더 합치기

선택한 캘린더를 호출한 카드 위치에서 하나의 카드로 합치고, 상단 탭으로 구분합니다.

사용자 동작
더보기에서 캘린더 합치기를 선택하고, 팝업에서 합칠 캘린더를 체크한 뒤 확인합니다.
개발 기준
탭은 성 뷸렛, 이름 말줄임, 더보기로 구성하며 내부 가로 스크롤은 만들지 않습니다.

09

합쳐진 캘린더 분리

그룹 탭의 개별 더보기에서 특정 탭만 독립 캘린더로 분리할 수 있습니다.

사용자 동작
탭의 더보기에서 분리하기를 누르면 해당 캘린더가 우측 독립 카드로 빠집니다.
개발 기준
단독 카드에서 분리하기를 누르면 변경 없이 토스트를 표시합니다. 전체 분리하기는 그룹 전체를 기본 카드로 되돌립니다.

10

개발 구현 기준

상태는 Provider Id, Active Provider Ids, Page Layouts, Width Map을 기준으로 분리 관리합니다.

상태 모델
Provider Id는 캘린더 식별자, Page Layouts는 페이지별 배치, Active Provider Ids는 노출 상태, Width Map은 저장 폭입니다.
예외 처리
최소 폭, 빈 페이지, 숨김 복원, 그룹 탭 최소 폭, before/after 드롭 위치를 명시적으로 계산합니다.
